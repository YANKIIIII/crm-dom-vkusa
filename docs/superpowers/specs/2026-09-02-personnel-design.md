# Персонал: зарплата, карточка, отпуска

Дата: 2026-09-02  
Статус: утверждено в обсуждении, ждёт ревью файла

## Цель

У руководителя появляется вкладка **Персонал**: личные данные сотрудников, расчёт зарплаты за месяц и календарь отпусков/отгулов всей команды.

Это не страница «Пользователи» (логины, роли, доступы). Учётки по-прежнему создаются только там. Сотрудник вкладку не видит.

## Вне скоупа (не в этой версии)

- Сотрудник смотрит свою ЗП или свои отпуска
- Закрытие / заморозка месяца
- Больничный и другие типы отсутствий кроме отпуска и отгула
- Табель часов по дням, норма месяца минус отсутствия
- Уведомления о дне рождения
- Дата приёма, паспорт, отдельные поля адреса
- Создание и удаление учёток из «Персонал»
- Экспорт в Excel, авансы, налоги, НДФЛ
- Пересечения отпусков одного человека как ошибка 400

## Формула

```text
ЗП = часы × ставка_месяца + (процент_месяца / 100) × продажи + бонус
```

- Часы и бонус вводит руководитель за выбранный месяц. Если строки месяца ещё нет — часы и бонус = 0.
- Ставка часа и процент — сначала из строки месяца. Если строки нет — из профиля. В профиле процент по умолчанию **3** (это 3% продаж, не 0,03%).
- Продажи считаются на лету, не хранятся.
- Отпуск и отгул на сумму не влияют.

Продажи сотрудника за месяц: сумма `total_amount` заказов, у которых:

- статус с `kind = completed` (`completed_order_status_codes()`);
- `seller_id` = этот пользователь;
- `completed_at` не пустой и попадает в календарный месяц в `Europe/Minsk`.

Открытые, отменённые и завершённые без `completed_at` не входят. Период аналитики по `order_date` сюда не подмешивать.

Деньги — `Decimal`, округление итога до копеек (2 знака). Валюта в UI как в остальной CRM (BYN).

## Данные

Новое Django-приложение `personnel`. Плюс поля на существующем `users.UserProfile`.

### UserProfile (расширение)

Уже есть `phone`. Добавить:

- `birthday` — `DateField`, пусто можно
- `notes` — текст, пусто можно
- `hourly_rate` — `DecimalField(12, 2)`, по умолчанию 0, не отрицательная
- `commission_percent` — `DecimalField(5, 2)`, по умолчанию `3.00`, диапазон 0…100

Таблица по-прежнему `user_profiles`. Профиль создаётся лениво: `ensure_profile(user)` (как `ensure_board`), вызов из `post_save` на `User` и перед отдачей API.

Удаление пользователя каскадом уносит профиль.

### MonthEntry

Одна строка на человека и календарный месяц.

Поля:

- `user` — FK на `users.User`, `CASCADE`
- `year` — целое, ≥ 2000
- `month` — целое 1…12
- `hours` — `DecimalField(6, 2)`, ≥ 0, по умолчанию 0
- `bonus` — `DecimalField(12, 2)`, ≥ 0, по умолчанию 0
- `hourly_rate` — копия ставки на этот месяц, ≥ 0
- `commission_percent` — копия процента на этот месяц, 0…100
- `created_at`, `updated_at`

Уникальность: `(user, year, month)`. Таблица `personnel_months`. Индекс по `(year, month)`.

Строка **не** создаётся при открытии экрана. Пока её нет, UI и API считают часы/бонус = 0, ставку и процент — из профиля. Первое сохранение месяца записывает часы, бонус и актуальные ставка/% (из тела запроса; если поля ставки не прислали — из профиля на момент сохранения). Правка ставки в профиле **не** переписывает уже сохранённые месяцы.

### Leave

Поля:

- `user` — FK на `users.User`, `CASCADE`
- `kind` — `vacation` | `time_off` (отпуск | отгул)
- `date_from`, `date_to` — даты, `date_to >= date_from`
- `comment` — текст, пусто можно
- `created_by` — FK на пользователя, `SET_NULL`
- `created_at`, `updated_at`

Таблица `personnel_leaves`. Индексы: `user`, `(date_from, date_to)`.

Пересечения у одного человека в первой версии разрешены.

Отсутствие **пересекает месяц**, если `date_from <= последний день месяца` и `date_to >= первый день месяца`. Так августовский отпуск до 5 сентября попадает в календарь сентября.

## Права

Новый модуль `personnel`:

- есть в `ALL_MODULES`
- **нет** в `GRANTABLE_MODULES` и в `SELLER_DEFAULT_MODULES`

Руководитель получает его вместе со всеми модулями. Сотруднику выдать нельзя: в форме «Пользователи» чекбокса «Персонал» нет. Пункт меню — из `effective_modules` после логина.

| Действие | Руководитель | Сотрудник |
|---|---|---|
| Меню, `/personnel`, API | да | нет пункта, UI редирект, API 403 |
| Список людей, карточка, месяц, календарь | да, все учётки | 403 |
| Создать учётку | нет, только «Пользователи» | нет |

Неактивные пользователи в списке есть (визуально приглушены), карточку и отсутствия открыть можно.

## API

Префикс `/api/v1/personnel/`. Все эндпоинты: `IsAuthenticated` + `HasModule('personnel')`.

Месяц в запросах: `year` и `month` (числа). Если не передали — текущий год и месяц в `Europe/Minsk`. Невалидные значения — 400.

Пагинации на этих списках нет.

### `GET /api/v1/personnel/employees/`

Список всех пользователей (включая неактивных), сортировка: активные сверху, затем фамилия, имя, `id`.

Элемент:

```text
{
  id, username, first_name, last_name, job_title, role, is_active,
  hours, bonus, hourly_rate, commission_percent,
  sales_total, pay_total,
  rate_source: "month" | "profile"
}
```

`hourly_rate` / `commission_percent` / `hours` / `bonus` — из `MonthEntry`, если есть, иначе часы/бонус 0 и ставка/% из профиля. `sales_total` и `pay_total` посчитаны на сервере. `rate_source` говорит, откуда ставка.

### `GET /api/v1/personnel/employees/<id>/`

Карточка. 404 если пользователя нет.

```text
{
  id, username, first_name, last_name, job_title, role, is_active,
  phone, birthday, notes,
  hourly_rate, commission_percent,          // текущие в профиле
  month: {
    year, month, hours, bonus,
    hourly_rate, commission_percent,        // эффективные для расчёта
    rate_source,
    sales_total, pay_total
  },
  leaves: [ /* отсутствия, пересекающие этот месяц */ ]
}
```

`year`/`month` — из query, иначе текущий месяц.

### `PATCH /api/v1/personnel/employees/<id>/`

Только профиль: `phone`, `birthday`, `notes`, `hourly_rate`, `commission_percent`. Нельзя менять username, пароль, роль, модули, `is_active`.

Аудит: `entity_type='personnel_profile'`.

### `PUT /api/v1/personnel/employees/<id>/months/<year>-<month>/`

Создать или обновить `MonthEntry`. Тело: `hours`, `bonus`; опционально `hourly_rate`, `commission_percent` (если нет — при создании взять из профиля, при обновлении оставить как было).

Ответ — эффективный месяц плюс `sales_total`, `pay_total`.

Аудит: `entity_type='personnel_month'`.

### `GET /api/v1/personnel/leaves/`

Query: `year`, `month`. Все отсутствия, пересекающие месяц, все пользователи. Для сетки календаря.

Элемент: `{ id, user, kind, date_from, date_to, comment }`. `user` — `{ id, first_name, last_name, username, is_active }`.

### `POST /api/v1/personnel/leaves/`

Обязательны `user`, `kind`, `date_from`, `date_to`. `comment` необязателен. `created_by` = текущий пользователь.

### `PATCH /api/v1/personnel/leaves/<id>/`

`kind`, даты, `comment`. Сменить человека нельзя.

### `DELETE /api/v1/personnel/leaves/<id>/`

Удалить.

Аудит CREATE / UPDATE / DELETE: `entity_type='personnel_leave'`.

Ошибки:

- нет модуля / не руководитель — 403
- нет пользователя или отпуска — 404
- отрицательные часы, бонус, ставка — 400
- процент вне 0…100 — 400
- `date_to < date_from` — 400
- неверный `kind` — 400
- неверный месяц в URL или query — 400

## Экран

Маршрут `/personnel`, `RoleRoute module="personnel"`. Пункт меню «Персонал», иконка `badge`, между «Справочники» и «Пользователи».

Переключатель месяца общий для раздела (по умолчанию текущий). Внутри две вкладки.

### Сотрудники

Слева список: ФИО (или username), ЗП за месяц, неактивные приглушены. Справа карточка выбранного:

- ФИО, должность или роль
- телефон, день рождения, заметка — сохранение по blur/кнопке как в карточках CRM
- текущие ставка ₽/ч и процент профиля
- часы и бонус выбранного месяца; ставка/% месяца, если строка уже есть (иначе показываем профиль и подпись, что ещё не сохраняли месяц)
- продажи и итог ЗП, формула расшифрована коротко (часы, процент с продаж, бонус)
- компактный список отсутствий, пересекающих месяц; «+ отпуск» / «+ отгул» открывают тот же диалог, что на календаре

Людей и пароли не создаём.

### Отпуска / отгулы

Сетка месяца: строка на каждого пользователя (как в списке сотрудников), колонки — дни месяца. Отпуск и отгул разным цветом (отпуск — спокойный синий/серый, отгул — акцент `#CC5E33` или бледный вариант, чтобы не спорить с сайдбаром). Полоска на диапазоне дат. Клик по пустому дню в строке — создать с предзаполненными человеком и датой. Клик по полоске — править или удалить (удаление с `confirm`).

Отсутствие, начавшееся в прошлом месяце, обрезается по левому краю сетки; уходящее в следующий — по правому.

## Ошибки в UI

Тосты как в остальной CRM. Пустые часы при первом заходе не ошибка. Нет сотрудников — пустой список и текст, что людей заводят в «Пользователи».

## Тесты

Бэкенд (pytest):

- формула: часы × ставка + % продаж + бонус, копейки
- продажи только completed + `completed_at` в месяце Минска; чужой продавец и отмена не входят
- без `MonthEntry` ставка из профиля, часы 0
- сохранённый месяц не меняется после правки профиля
- сотрудник — 403 на все URL
- отпуск через границу месяцев попадает в оба `GET leaves`
- `date_to < date_from` — 400

Фронт: страница в оболочке с вкладками, список+карточка, сетка календаря, модуль в сайдбаре только у руководителя.
